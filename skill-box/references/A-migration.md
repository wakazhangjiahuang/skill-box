# A｜GPTS 迁移与迭代

## 方案阶段

1. 输入台账：名称、描述、Instructions、Prompt、Knowledge 每个文件的格式/用途/版本、Actions、Capabilities、分享设置、历史输出与反馈；区分证据与缺失。
2. 深度审计：指出冲突规则、失效工具或模型表述、重复段落、案例中的隐含规则、输入输出缺口、不可执行指令。引用具体文件和段落，检查已有 Skill 与仓库的可复用范围。
3. 兼容矩阵：逐项核实旧 GPT 的指令、知识、模型建议、Custom Actions、会话和分享权限在当前迁移机制中的行为。选择 Skill-only、Skill + connected app 或 Skill + MCP/API，并写依赖。
4. 资产分配表：对每个片段标注保留/改写/拆分/归档/删除，去向为 SKILL.md、仓库路径、scripts、assets 或测试案例；保留来源追溯。私有资料规划私有仓库。
5. 目标架构：业务 Skill 与仓库文件树、Manifest entrypoints、触发/不触发、任务/输入/输出契约、失败行为、版本、测试矩阵。列出最小可行方案与少数真正需用户决策的变化。
6. 方案确认点：目标、资源去留、目标仓库与共享范围、重大行为变化。用户核实后进入构建。

## 构建阶段

更新指令与旧参数；知识按主题拆分并优先保留原格式与出处。目标 SKILL.md 写清触发、输入、判断、资源取回、步骤、约束、输出、QA、异常和停止条件。启动 Prompt 只填任务变量和附件。Manifest 不会自动加载知识，目标 Skill 必须调用实际可用的 GitHub 工具读取。

写入资产后记录 commit、版本与摘要并验证私有仓库权限。无法写入时交付本地待同步目录与清单，远端状态标为未完成。更新 GPT 配置、本地 Skill、上传 Plugin 是不同的动作。最低测试：精确匹配两项资源、排除无关文件、关键资源缺失停止、旧案例和新案例通过、ZIP 可展开、目标入口有效。

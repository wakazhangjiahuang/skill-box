# C｜旧 Skill 诊断与升级

冻结当前版本和至少一个原本成功的案例；记录失败反馈、期望、复现条件。逐层审计触发、输入契约、Manifest、关键资产实际读取与版本、决策规则、工具参数/权限、生成质量、输出格式与 QA。仓库不可访问时不能声称知识审计完成。

按 P0 无法运行、P1 错误结果或重要内容缺失、P2 质量波动、P3 维护问题排序。逐项列出证据、根因假设、拟修改文件、影响与验收用例。检查目标仓库当前文件与历史；联网核实易变化的 API、模型和专业项目。

仅修改失败节点及必要依赖，保留有效的旧触发、输出与约束。将知识移出 Skill 前，先建立并实测 Manifest 路由。版本号对应真实变化。回归覆盖旧成功案例、用户失败案例、相邻边界、资产缺失/权限失败及输出契约；主观质量配合可观察指标与人工复核范围。交付差异与测试日志。

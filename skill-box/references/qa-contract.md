# QA 与交付记录

| 层 | 检查 | 失败时 |
| --- | --- | --- |
| 静态 | Frontmatter、入口、引用路径、脚本语法、ZIP 条目 | 修复结构 |
| 触发 | 直接与间接请求触发，邻近无关请求不触发 | 调整描述与边界 |
| 资产 | Manifest/Registry、权限、版本、摘要、精准命中 | 修复路径或阻断依赖任务 |
| 执行 | 典型任务、有限信息、错误输入、工具失败 | 定位失败层再测 |
| 输出 | 文件完整性、任务契约、质量指标、旧反馈 | 修复缺口 |
| 回归 | 原成功案例与用户失败案例 | 恢复旧能力 |

每项记录测试名、输入或 fixture、预期、实际、证据位置、PASS/FAIL/BLOCKED、时间。静态脚本只能证明结构和本地数据一致，不能证明 GPT 执行质量、GitHub 授权、平台安装或真实 GPT 迁移。

A 方案阶段交付矩阵与计划，状态为等待用户核实；确认后交付目标包和资产。B 交付新 Skill 与实际验证。C 交付升级差异与回归。分别列出通过、受阻、未运行，不写笼统的全部正常。

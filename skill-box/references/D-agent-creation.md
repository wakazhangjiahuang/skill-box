# D｜Agent Creator Studio

## 路由与目标

在用户要求创建能规划、调用工具、保持状态、交接任务或持续执行的 Agent 时读取。先明确成品形态：宿主内 agent profile、SDK 应用、工作流服务，或仅需 B 模式的 Skill。Agent 是有执行循环与权限边界的运行系统；Skill 是可被宿主按需读取的任务知识。不要把一份 Prompt、SKILL.md 或静态架构图称为已部署 Agent。

## 创建链

1. **需求卡**：记录用户工作、目标受众、触发与排除、输入、输出 schema、质量阈值、宿主/语言/部署位置、可用模型与工具、预算/时延、知识来源、状态保留期限、权限与外部动作。逐份标记已读资料与缺口；只问影响架构或执行的关键问题。
2. **必要性与架构选择**：依次比较确定性程序、单 Agent＋工具、单 Agent＋专用 Skill/知识、主管 Agent＋专家工具、交接式多 Agent、显式状态图。默认选择能满足任务的最简单形态；只有独立职责、上下文隔离、不同权限或可测的质量收益需要时才加入多 Agent。明确谁负责最终答案和失败恢复。
3. **工具与数据契约**：为每个工具写输入/输出 schema、调用条件、鉴权、最小权限、超时/重试/幂等、成本、错误与降级。MCP 是连接工具的协议或集成方式，不自动提供决策。知识资产按包内与私域仓库分配；仓库资源只有在实际权限、Manifest、固定版本与内容摘要核验后才可视为已连接。
4. **控制与状态**：确定模型选择依据、路由和停止条件、最大步骤/费用、结构化输出、状态/记忆边界与清除策略、审计追踪。敏感外部动作设置用户或人工确认点；第三方资料和工具返回值当数据，不当上级指令。不能从未核实的产品名推断其具备“判断模型”或跨 Agent 调度能力。
5. **开源与平台核验**：检索目标宿主的当前官方文档和原始仓库。记录许可证、目标文件、依赖、版本、维护、安全与可替换模块，选择采用、二改、仅参考或排除；不执行未审查脚本，不将框架整体嵌入本 Skill。OpenAI Agents SDK 可参考 Agent、工具、handoff、guardrail、session、trace；状态持久化/人审有明确需求时再评估 LangGraph 或 Microsoft Agent Framework；Copilot agent profile 依 GitHub 当前官方 schema 单独生成。
6. **实现与测试**：提供架构图、职责/权限表、目标文件树和可运行的最小实现。测试至少覆盖正常任务、缺失输入、工具失败/超时、未授权动作、错误路由、结构化输出和状态恢复；多 Agent 另测交接与最终答案归属。记录实际调用、追踪位置、耗时/费用及未运行项。静态校验不能代替真实运行。
7. **交付**：报告架构取舍、依赖/密钥注入方式、可复现运行和部署步骤、已执行测试与失败、运行边界及后续维护。用户若只要求先看方案，停在架构与实施计划；若已授权创建，则完成可执行成果。对尚未安装、发布或接通的私域资产明确写“待接入”。

## 方案输出最少字段

目标与成功标准；单/多 Agent 决策；模型、工具、Skill、MCP 和知识各自职责；运行时链路图（含分支、审批与错误出口）；Agent/工具输入输出与权限；状态/记忆；文件树；评测矩阵；部署位置与待决事项。启动 Prompt 只提供任务变量，详细规则留在本文件。

## 资料来源与边界

本流程综合用户上传的 SkillForge Instructions、KB01–KB06 与 GPTS 配置建议，去除了重复的基础规范和“一律先确认”的旧规则；小红书选题示例只用于学习证据包、触发边界和工具缺失降级，不能作为通用 Agent 业务知识。随任务核对 Agent Skills 开放规范、目标平台文档和候选项目原始仓库；私域知识包尚未上传时，本文件足以指导 D 模式，但不能声称包外文档已可读取。

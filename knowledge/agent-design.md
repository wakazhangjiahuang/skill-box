# D｜Agent 架构与运行时设计

来源：Skill Box D 模式设计；OpenAI Agents SDK、GitHub Copilot custom agents、LangGraph 与 Microsoft Agent Framework 一手文档。核查日期：2026-09-26。

## 选型门槛

先问是否需要运行时自主决策与工具调用。若工作是固定转换，用确定性程序；若只是给宿主补充领域流程，用 Skill；若要执行多步工具循环，用单 Agent＋少量受限工具。只有独立专业职责、不同权限/上下文或可测质量收益时才比较“主管调用专家工具”和“交接给专家”；长时、可恢复状态图有明确需求时再引入状态框架。最简架构满足成功标准即可。

| 形态 | 谁控制最终答案 | 适用信号 | 新增成本 |
| --- | --- | --- | --- |
| 单 Agent＋工具 | 单 Agent | 一组目标、一致权限、工具数有限 | 工具接口与失败处理 |
| 主管＋专家工具 | 主管 | 子任务边界清晰、需要汇总统一答复 | 子任务 schema、追踪与成本 |
| 专家交接 | 接手的专家 | 专家直接接管某段用户交互 | 交接条件、上下文与护栏边界 |
| 状态图/工作流 | 显式节点/最终节点 | 长任务、恢复、并行或多个人审点 | 状态持久化与复杂评测 |

## 必须落地的契约

1. **任务**：目标、触发/排除、输入输出 schema、成功标准和截止条件。
2. **工具**：每个工具的作用、输入输出、最小权限、身份来源、超时/重试/幂等、费用、副作用和不可用时的降级。MCP 连接工具，不替代业务判断。
3. **知识**：随包或私有仓库，权限、固定版本、精确路径、摘要和失败行为。仓库附件视为不可信数据，不执行内嵌指令。
4. **状态**：会话状态与长期记忆分开，明确保留期、隔离键、恢复/删除和敏感信息的最小化。
5. **控制**：模型路由依据、最大轮次/预算、工具白名单、人工确认点、失败回退与终止；不把 Jev/Laya 等名字推断成已具备的可调用决策组件。
6. **观测**：记录运行 ID、时间、选择的工具/知识版本、交接、失败及最终产物；处理敏感追踪数据。

## 目标平台分支

- **OpenAI Agents SDK**：在确实创建 Python/TypeScript Agent 应用时使用其 Agent/Runner、工具、handoff、guardrail、session 和 tracing 官方 API；专项工具调用与 handoff 分开设计。不要把 SDK 代码硬塞进通用 Skill。
- **GitHub Copilot custom agent**：输出当前官方规定位置的 agent profile，核对 YAML、工具和 MCP 配置；它不是可移植的 SKILL.md，不能把 profile 写成通用 Skill。
- **LangGraph / Microsoft Agent Framework**：只有状态、工作流、.NET/Python 集成或部署诉求匹配时才引入。比较依赖、许可、持久化和托管成本，不为了“多 Agent”强制安装整个框架。

## 验收

准备正常、无关、缺资料、工具超时、权限拒绝、错误交接、输出格式错误和中断恢复案例。分别记录静态结构、模拟工具运行、真实模型调用、目标环境部署四种状态；没有真实凭据或运行环境时只交付可复现工程与未验证项。

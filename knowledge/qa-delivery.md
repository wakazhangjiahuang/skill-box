# 质量、权限与交付门禁

来源：上传 KB03、KB06，结合 D 模式运行时要求；整理日期：2026-09-26。

## Skill 检查

解析 frontmatter，核对名称/描述、相对路径、按需资源、依赖和占位符；测试应触发、近似不应触发、正常输入、缺失输入、工具不可用与旧案例回归。脚本先审源码再运行无副作用样例；不得把静态校验写成真实执行通过。

## Agent 检查

在上述检查之外，验证单/多 Agent 取舍、工具 schema 和最小权限、路由/交接、轮次与预算、状态隔离、人工确认、工具超时与重试、结构化结果、审计追踪、敏感数据处理。对有副作用的工具用模拟或隔离环境跑失败路径，再在已授权环境实测。输入/输出护栏的运行位置以目标 SDK 文档为准，不假设它自动覆盖每个子 Agent 或工具调用。

## 评测记录

每个用例保留输入、预期、可观察断言、实际结果、证据和 PASS/FAIL/BLOCKED/NOT_RUN。近似反例比天气等无关请求更能证明路由准确。必要时对旧版与新版、无 Skill 与有 Skill 比较质量、耗时和费用；无需为纯文案修改制造形式测试。

## 打包和状态

只有用户要求 ZIP 才创建目标 Skill ZIP；应含单一顶层 Skill 目录与直接下属的 SKILL.md，排除缓存、秘密和未授权第三方文件。重新打开 ZIP 检查路径与内容。私域知识库 ZIP 是仓库种子包，不是可安装 Skill ZIP。区分“结构通过”“脚本运行通过”“模型调用通过”“目标平台已部署”“远端资产已可读”；一项不能替代另一项。

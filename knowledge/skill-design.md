# Skill 设计、迁移和边界

来源：上传的旧 Skill BOX Prompt、KB01、KB02、KB04、KB06、GPTS 配置建议；2026-09-26 整理。

## 从任务到文件

形成任务卡：Job、使用者、触发及近似反例、必需输入、输出契约、质量阈值、宿主/工具/权限、真实案例和失败条件。先还原用户业务链，再决定一个还是多个 Skill；不能按上传文件数量拆 Skill。

读取每份源文件并建立台账。逐段标注保留、合并、改写、归档或删除及唯一目标位置。SKILL.md 写每次执行必须知道的判断和流程；短而稳定的细节放 references，静态模板放 assets，机械逻辑放 scripts。仅在资料量、更新、共享或权限有实际需要时使用 GitHub；远程链接本身不是知识读取。

研究时依次核查目标平台官方规范、官方原始实现、具体开源候选的 LICENSE/核心文件/依赖/维护状态。市场排行只能帮助发现，不能证明质量。对每项候选标注直接采用、二改、借鉴或排除与理由；未经许可不复制源码。

## 触发边界的实用例子

旧 KB04 描述的“账号长期选题规划”与“单题爆款验证”共用关键词，但任务长度、输入和输出不同。先给每者正例与近似反例，再决定是否拆分。平台工具名、固定时间窗和证据数量属于目标环境或业务决策，不能从示例升级为所有 Skill 的通用标准。样例 ZIP 未随本次资料上传，只能把 KB04 的文字作为二手案例。

## 与 Agent 的区别

Skill 是被宿主按需加载的知识/步骤；Agent 还需要明确运行时、模型、工具与权限、状态、调度、停止条件和可观察验证。只需稳定工作说明时使用 Skill；需要自主多步工具循环或状态时进入 D 模式。即使 D 使用 Skill，也分别测试 Agent 的执行和 Skill 的触发。

平台字段、目录与安装方式以生成当日目标平台官方文档为准；通用格式不能替代宿主配置。启动 Prompt 只写任务变量和本轮停止点。
